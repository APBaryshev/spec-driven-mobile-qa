# Proposal

## Why

TaskFlow нужен первый законченный пользовательский путь: создать задачу и видеть её после повторного запуска приложения. Это изменение закладывает поддерживаемую основу мобильного приложения и демонстрирует полный проверяемый цикл от требований и архитектурных решений до реализации и подтверждения качества в последующем этапе.

## What Changes

- Создать приложение React Native + TypeScript + Expo с первым проверяемым выпуском для Android.
- Предоставить создание и просмотр задач без сети для одного пользователя на одном устройстве.
- Принимать однострочное название длиной 1–100 кодовых точек Unicode после удаления пробельных символов по краям, запрещая внутренние переводы строк без потери ввода; разрешить одинаковые названия, сохраняя отдельную идентичность задач.
- Показывать новые задачи сверху и восстанавливать сохранённый список при повторном запуске.
- Подтверждать создание после успешной постоянной записи либо контрольного чтения, доказывающего сохранение отправленного снимка. После ошибки записи блокировать новые записи до определения фактического состояния; различать загрузку, пустой список, сохранение, проверку результата и ошибки с соответствующим повтором.
- После остановки процесса, в том числе во время проверки результата, выполнять обычную безопасную загрузку постоянного состояния без автоматического повтора неподтверждённого создания.
- Разделить UI, управление задачами и хранение; использовать AsyncStorage за изолированным интерфейсом.
- Выполнять контрольное чтение только после завершения ошибочной записи, при одном владельце записи и отсутствии внешних писателей; механизм не является полноценной транзакционной защитой.
- Предусмотреть unit/integration-проверки внутренних ID и согласования хранения, E2E-проверки пользовательского поведения, а также публичную документацию решений и результатов без технических элементов UI исключительно ради тестов.

Вне границ: редактирование, удаление, завершение задач, сроки, поиск, аккаунты, backend, синхронизация, несколько пользователей, выпуск iOS, гарантии восстановления после переустановки или очистки данных, дополнительные агентные фреймворки. Redux и DI-контейнер не требуются. Это изменение не вводит отдельную capability для тестового инструмента.

## Capabilities

### New Capabilities

- `task-management`: создание валидных задач, просмотр упорядоченного списка, локальная сохранность и восстановление, понятное поведение при загрузке и сбоях.

### Modified Capabilities

Нет: действующие спецификации отсутствуют.

## Impact

Сейчас репозиторий содержит README и OpenSpec, но не содержит исходного приложения, зависимостей или тестов. Будущая реализация добавит Expo-проект, локальные зависимости хранения, один функциональный модуль задач и проверки разных уровней. Серверных API и внешних интеграций нет; архитектура по возможности останется кроссплатформенной без заявления о проверенной поддержке iOS.

Планирование ограничено текущим репозиторием. Настоящий change содержит только плановые артефакты; код, сборка и выполнение тестов относятся к отдельно разрешаемой реализации.
