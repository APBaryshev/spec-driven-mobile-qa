# Tasks

Порядок групп задаёт зависимости. Все пункты относятся к будущей реализации; наличие этого файла не означает, что работы или проверки выполнены. Источник поведения — [spec.md](specs/task-management/spec.md), технических решений — [design.md](design.md). Однострочное название, длина в кодовых точках Unicode и механизм согласования подтверждены владельцем. UX по умолчанию описан в design. Новые записи разрешаются только после определения исхода предыдущей попытки; после нового запуска неподтверждённое создание автоматически не повторяется.

## 4. Управление состоянием и асинхронный жизненный цикл

- [x] 4.1 Реализовать useTasks/reducer: загрузка, ready, ошибка чтения и повтор; не разрешать создание до успешного чтения. Готово, когда unit/integration-тесты с управляемыми promises подтверждают TM-07/TM-08, отсутствие стартовой записи пустого списка, защиту от повторного retry и игнорирование устаревших результатов после cleanup/Strict Mode.
- [x] 4.2 Реализовать создание с синхронным guard до await, сохранением исходного/отправленного снимков и публикацией только после подтверждения. Готово, когда integration-тесты проверяют TM-03/TM-04: быстрые отправки дают одну операцию, медленная запись не создаёт преждевременного успеха, блокировка не снимается при неопределённом исходе и последовательные создания не теряют предыдущие задачи.
- [x] 4.3 Реализовать контрольное чтение после завершения ошибочной записи с сопоставлением полного исходного/отправленного снимков. Готово, когда integration-тесты подтверждают: найден отправленный — успех без новой записи; найден исходный — ошибка с исправлением/повтором (тот же ID для неизменённого ввода); ошибка чтения/повреждённый/неожиданный снимок — блокировка и повтор только чтения без параллельных проверок. После определения исхода изменённый ввод не теряет фактически записанную задачу и не создаёт дубликаты; сверяются все ID/названия/порядок и последовательность save/load, timeout не разрешает согласование параллельно записи (TM-03–TM-05).
- [x] 4.4 Зафиксировать lifecycle-поведение и расширить docs/traceability.md проверками TM-03–TM-09/TM-12. Готово, когда integration-тесты новой сессии с тем же хранилищем после прерывания контрольного чтения покрывают сохранённый/исходный снимок и ошибку стартового чтения: точные ID/названия/порядок восстанавливаются либо показывается ошибка без нового save и без автоматического повтора создания. Возврат из фона сохраняет блокировку неизвестного исхода без параллельных операций; документация отличает проверки сессии от нативного E2E.
