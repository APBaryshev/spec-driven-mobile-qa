# Хранение задач

Реализация: [taskStorage.ts](../src/features/tasks/taskStorage.ts).
Чистая [модель](../src/features/tasks/model.ts) не зависит от нативного хранения.
Контракт `TaskStorage` содержит только `load(): Promise<readonly Task[]>` и
`save(tasks: readonly Task[]): Promise<void>`. Подключение к владельцу состояния
и UI остаётся в группах 4–5.

## Формат v1

Единственный ключ — `taskflow.tasks`. Значение — JSON полного снимка:

```json
{"schemaVersion":1,"tasks":[{"id":"example-b","title":"B"},{"id":"example-a","title":"A"}]}
```

Массив хранит порядок отображения. `save` заменяет весь снимок, сохраняет ID,
названия и порядок без изменений; `save([])` записывает явный пустой снимок.
`load` возвращает пустой список только при отсутствии ключа либо валидном пустом
массиве v1. Начальное чтение ничего не записывает.

Конверт содержит только `schemaVersion` и `tasks`, запись — только `id` и `title`.
ID — непустая, не состоящая только из пробелов строка, уникальная внутри снимка;
чтение не генерирует и не нормализует ID, не требует специального UUID-формата.
Название проверяется существующей моделью: 1–100 кодовых точек, без внутренних
LF/CR/CRLF/VT/FF/NEL/LS/PS. Сохранённое название должно уже быть нормализовано
через ECMAScript trim; названия с пробелами по краям отклоняются, не исправляются.
Внутренние пробелы, табы, регистр и Unicode-представление сохраняются.

Некорректный JSON (включая пустую строку), неизвестная версия, неверные поля,
невалидная задача или повторяющийся ID отклоняют весь снимок. Нет автоматического
удаления, пропуска записей, замены пустым списком или миграции. Повтор чтения может
помочь при временном I/O-сбое, но не исправляет формат. Изменение формата потребует
отдельной явной миграции с сохранением исходных данных; несовместимый downgrade
не должен очищать данные.

## Адаптер и завершение операций

Добавлена точная версия `@react-native-async-storage/async-storage` **2.2.0**:
она указана в `node_modules/expo/bundledNativeModules.json` установленного Expo
**58.0.22**, рекомендована [Expo](https://docs.expo.dev/versions/latest/sdk/async-storage/)
и принимает React Native 0.88.1 по peer range. Версия зафиксирована в manifest и
единственном npm lockfile. Это необходимое key-value хранилище из design,
дополнительные архитектурные слои не вводятся.

Чтение выполняется через `multiGet([key])`: в установленной версии `getItem`
превращает `""` в `null`, а `multiGet` сохраняет пустую строку для проверки JSON.
Различие подтверждено тестом `empty string` на настоящей JS-обёртке пакета.

`save` ожидает `setItem` и разрешает promise только после успешного native
callback. Нет timeout, фонового повторения, очереди повторов или скрытого чтения.
Rejection не доказывает отсутствия записи: тестируются как отказ до изменения,
так и фактическая запись с ошибкой ответа. Для обеих веток проверено отсутствие
новых вызовов I/O и изменения значения после завершения в управляемой среде.

При review исходников установленной 2.2.0 проверены:

- [AsyncStorage.native.ts](https://github.com/react-native-async-storage/async-storage/blob/3c9560c8874cabb1200b5121815f932b397cf89e/packages/default-storage/src/AsyncStorage.native.ts): `setItem` завершает promise из callback `multiSet`, без поздней повторной записи.
- [AsyncStorageModule.java](https://github.com/react-native-async-storage/async-storage/blob/3c9560c8874cabb1200b5121815f932b397cf89e/packages/default-storage/android/src/main/java/com/reactnativecommunity/asyncstorage/AsyncStorageModule.java): обычный Android backend завершает `endTransaction()` в `finally` перед callback успеха/ошибки; после callback запись этой операции не продолжается.
- [config.gradle](https://github.com/react-native-async-storage/async-storage/blob/3c9560c8874cabb1200b5121815f932b397cf89e/packages/default-storage/android/config.gradle): `AsyncStorage_useNextStorage` по умолчанию `false`. Альтернативный [StorageModule.kt](https://github.com/react-native-async-storage/async-storage/blob/3c9560c8874cabb1200b5121815f932b397cf89e/packages/default-storage/android/src/main/java/com/reactnativecommunity/asyncstorage/next/StorageModule.kt) вызывает callback после suspend `storage.setValues`, исключения обрабатываются coroutine handler. Переключение backend требует повторной проверки интеграции.

Это review порядка завершения и Jest-проверка JS-контракта, а не выполненный
нативный Android-тест. Установленную сборку и фактическую конфигурацию backend
ещё предстоит проверить в группе 6.

Контрольное чтение после ошибки будет реализовано владельцем состояния в 4.3.
Его предпосылки: запись уже завершилась, один владелец, нет внешних писателей и
перекрывающихся операций. Timeout не отменяет нативную запись. Владелец должен
сравнивать весь исходный и отправленный снимки: ID, названия и порядок.
В текущем адаптере согласование и автоматические повторы отсутствуют.

## Ошибки и ограничения

`TaskStorageError.category` — `read` (ошибка чтения I/O), `write` (ошибка записи
I/O), `format` (невосстановимый формат или невалидный исходящий снимок до I/O).
Сообщение фиксированное, например `Task storage read failed`. Исходное исключение
не сохраняется в `cause` или иных полях; сырые сообщения JSON parser/AsyncStorage,
названия, ID, сохранённые снимки и токены не включаются в диагностику адаптера.
Адаптер сам ничего не логирует. Для пользовательских сообщений будущий UI должен
использовать категорию, а не показывать техническую ошибку.

AsyncStorage не шифрует данные и не является хранилищем секретов.
Каждый `save` имеет стоимость полного снимка. Нет транзакционных гарантий
протокола приложения, CAS, защиты от нескольких писателей, резервной копии или
обещания устойчивости к аппаратному сбою. Очистка данных, переустановка, черновик
и неподтверждённая операция после завершения процесса вне гарантий сохранности.

Сериализация, восстановление и внутренние ID проверены в unit/integration с
синтетическими данными и управляемой нативной key-value границей. Нативная
сохранность после Android stop/launch, автономность без сети и возврат из фона
**не проверены**. Соответствия конкретным тестам и результаты —
[traceability.md](traceability.md).
